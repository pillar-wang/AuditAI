## 服务端改动与旧客户端的兼容性核验（重要）

部署后补做了一项**向后兼容核验**：我在服务端给 `PushImage`/`PushPdf` 新增了 `OutOfDate` 返回，必须确认**现网旧客户端**不会因此崩。

- `Syncer.Push(Image)`（`Syncer.cs:965-968`）与 `Syncer.Push(Pdf)`（`:1006-1009`）**都已处理 `OutOfDate`**，返回 `PushResult.OutOfDate` 而非抛异常。

## 云端同步功能代码审查（AuditAI 首轮）

只读审查了客户端 + 服务端（`.tmp-server` = AuditApiServer）的云端同步全链路，产出 `云端同步代码审查报告_20260916.md`。

### 架构要点（后续排查可复用）

- 客户端同步核心 = `ProjectModel/Auditai.Model/Syncer.cs`（2816 行，增量打包 + Merge）
- 路由层 = `AuditAI.LocalDataStore/StorageRouter.cs`（Local/Server 模式分流，`OnServerModeActivated` 回调启用 Syncer）
- HTTP 层 = `WebApiLib/Auditai.Util/WebApiClient.cs`；`httpClient.Timeout = Infinite`，每请求经 `TimeoutHandler` 用 `RequestOptions.Timeout` 超时，超时被包装为 `HttpRequestException(TimeoutException)`
- 服务端同步服务 = `.tmp-server/Services/TableSyncService.cs` / `DocumentSyncService.cs`
- 编排层 = `AuditAI/Auditai.UI.Platform/MainForm.cs`：`SyncProjects`(2752) → `SyncProjectImpl`(2926) → `GetTableTask`(3194) / `ContinueWithTable`(3164)
- 进度窗 = `CommonControls/Auditai.UI.Controls/ProgressForm2.cs`：`TaskRunner` 用 `Task.Run`（同步逻辑跑在线程池），异常经 `CloseWithException` → `CaseCloseException.Throw()` 在 ShowDialog 返回后**原样重抛**

### 确认的关键结论

1. **乐观锁实现是正确的**：服务端 `UPDATE ... AND Version=@expected` 在事务内，affected=0 回滚重试；无静默丢数据的竞态。
2. **P0 越权写入**：GET 版 `PushTable`/`PushDocument`（Program.cs:3877/4360）用 query 参数 `projectId` 鉴权，但写库目标取自 protobuf（`TableSyncService.cs:397`、`DocumentSyncService.cs:325`），两者无一致性断言。POST 的 Quick 变体是安全的。
3. **批量同步无失败隔离**：`SyncProjects` 的 `foreach` 只有 `finally` 没有 `catch`；`SyncProjectImpl` 里 `Syncer.Pull(proj)`(2951)、4 次 `QueryVersion`(2970-2989) 无 try 包裹 → 任一异常 → `TaskRunner` 重抛 → `SyncProjects.catch(Exception)` → **弹窗后 return，剩余项目全部静默跳过**。
4. **关闭单个项目路径**：`SyncProject`(2867) **只 catch `HttpRequestException`**，而 `ServerException : Exception`（`DTO/Auditai.DTO/ServerException.cs:5`）不是它的子类 → 逃逸到 `ribbonButton.Click += async delegate`（:2397）→ async void 未处理异常。`View_FormClosing`(:5858) 和 `SyncProjects`(:2831) 都有通用 catch，只有这里漏了。
5. **大数据量瓶颈**：服务端 Pull 是**全量**（`TableSyncService.cs:138-199` 注释写明 MVP 返回完整表）；`PushTable`/`PullTable` 客户端超时各 5 分钟，`QueryVersion` 仅 30 秒；服务端 `QueryTableVersions` 是 `foreach` 逐条调 `QueryLatestTargetVersionAsync`，且**每条都新建并 Open 一个 SQLite 连接**（`Program.cs:4255-4269` + `6037-6051`）。
6. **服务端并发缺陷**：首建表 INSERT 主键冲突抛异常（不走 affected==0 重试）→ 500；首建文档的 UPDATE 缺 `AND Version=@expected`（`DocumentSyncService.cs:401`，已存在文档路径 :398 是对的）。

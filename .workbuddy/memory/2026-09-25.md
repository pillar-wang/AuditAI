### 留给用户决策的问题（本轮未改，改动涉及会计口径/交互设计，不宜擅动）

1. **组合期初的期间口径不一致（P1）**：`MultiDimEditor` 的账期起止是可改的月份选择器；单轴科目期初取 `tbs.Start`（账期起始日前一日余额），而**有组合期初表的科目**期初取 `ledger.ComboOpeningBalances`，其来源是导入表的「年初借方/贷方余额」列（`LedgerBuilder3.cs:1688-1689`，无日期维度）→ 把起始月改到年中时，同一张多维报表里两种口径并存、与余额表勾稽不上。
2. **期初余额被编辑后组合期初不重算（P1）**：`LedgerViewer.ModifyBeginBalance` 只改 `Ledger.InitialBalance`（含辅助项），`ItemComboBalance` 表只在 `Ledger.Save()` 时用内存 `ComboOpeningBalances` 无条件全删全插重写，而内存里那份从未被改写过。
3. **组合期初读取失败 + 保存全删全插的组合（P1）**：`LedgerDAL.cs:284-335` 读异常只写 Debug 日志并留空；`472-486` / `623-637` 保存无条件 `DELETE FROM ItemComboBalance` 后按内存重建 → 一次瞬时读失败后，用户任意一次 `Ledger.Save()` 会把这些组合期初余额永久清除。建议改脏标记增量写，或读取失败即报错。
4. **合计行口径（P1）**：无组合期初表的科目由单轴路径逐类别生成期初组，而每个类别的项余额合计=该科目余额 → k 个类别则合计期初 = k× 科目余额，与余额表不符。
5. **`frmRiskCheckRuleEditor` 没有「说明(Note)」输入控件**：`OnOk` 从不写 `_rule.Note`，也不读；但 `RiskCheckEngine` 会把它填进结果的 `RuleNote`，结果表/导出都显示这一列 → 该列恒空。字段本身已持久化（`RiskCheckRule.note`），缺的只是录入入口。
6. **`FormulaManagerTransitional` 收敛范围收窄（P1，需实测）**：由「每轮全量重算所有宿主」改为「变化宿主 + `ReferredBy` 依赖闭包」，正确性完全押在 `ReferredBy` 覆盖全部依赖（填充公式生成的明细行/列、VLookUp/SumIf 间接依赖）上，否则会静默残留旧值。
7. **`frmImport` 移除了列宽自适应**：删掉了 `grdBalance/grdVoucher/grdAuxiliary.BindAutoSizeColsFill(this)`，全表单再无 Resize 绑定（只剩 `AutoSizeColsFill()` 一次性调用）；同目录 `frmBalanceEditor.cs:118`、`MultiDimEditor.cs:416` 仍在用 → 疑似无意删除。
8. **性能**：`RiskCheckEngine.MatchCode`（`RiskCheckEngine.cs:499-510`）在 `FilterAccounts` 的 `codePatterns.Any(...)` 里**每科目每模式都 `new Regex`** 且不缓存；`MultiDimensionQuery.cs:122` 只用 `tbs.Start` 却调 `GetTrialBalanceSheet`（内部多算 Debit/Credit/End，各含一次全量凭证扫描 + 余额克隆）。
